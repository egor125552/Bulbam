# Журнал изменений Бульбама

## Версия 0.7.3

Исправлено:

- возвращены настоящие экраны категорий настроек из ранее подготовленной ветки: при открытии виден список категорий, а после выбора показывается только выбранный раздел, без длинной ленты всех настроек;
- разделы смены пароля и микрофона снова открываются отдельными экранами с кнопкой назад; диагностика вынесена в собственную категорию;
- настройка статуса В сети размещена в разделе Основные, а раздел Приглашения по-прежнему показывается только тем, кому он доступен;
- исходящий звонок больше не пытается определять открытый чат по всей видимой строке @username · В сети: открытый диалог передаёт стабильный идентификатор разговора, поэтому добавление статуса присутствия не ломает звонок;
- сохранён совместимый запасной путь для старой закэшированной разметки, но он отделяет username от текста статуса и не принимает всю строку за имя пользователя;
- переход из уведомления о запросе восстановления открывает именно раздел Безопасность, поэтому очередь заявок не оказывается скрытой внутри другого экрана;
- обновлён идентификатор загрузки клиентского модуля, чтобы браузер не удерживал старую версию интерфейса после выпуска.

Проверено:

- 129 из 129 автоматических тестов проходят при нормальном лимите времени для интеграционного теста присутствия;
- TypeScript, синтаксис клиентского JavaScript и сухая сборка Cloudflare Worker проходят без ошибок.

## Версия 0.7.2

Исправлено:

- у владельца и администратора в навигации настроек появился прямой пункт Приглашения, который открывает уже существующее создание одноразового кода;
- обычным участникам этот пункт по-прежнему не показывается, поэтому права существующей системы приглашений не расширены;
- подтверждено, что текущий аккаунт владельца на сервере имеет право создавать приглашения: проблема была в доступе к функции из интерфейса, а не в серверном запрете;
- добавлена регрессионная проверка доступности пункта Приглашения для владельца.

Не добавлялось:

- управление правом приглашать отдельно для каждого пользователя. Это отдельная будущая возможность, а версия 0.7.2 исправляет только доступ владельца к уже существующим приглашениям.

## Версия 0.7.1

Исправлено:

- экран регистрации больше не содержит персональные примеры с именем Егор: используются нейтральные примеры пользователя и отображаемого имени; само отображаемое имя по-прежнему можно менять после регистрации;
- переключатель подробных подсказок теперь действует на дополнительные пояснения во всём интерфейсе, а не только на запись голосовых; при выключении важные ошибки и сообщения состояния остаются, а при повторном включении связи VoiceOver с подсказками восстанавливаются;
- статус В сети и последняя активность получили отдельную видимую строку в карточке чата и не выпадают из её разметки;
- последнее исходящее сообщение прямо в списке чатов показывает реальное состояние отправлено, доставлено или прочитано;
- прочтение теперь подтверждается сервером отдельной квитанцией и обновляется у отправителя как в открытом диалоге, так и в списке чатов;
- исходящий звонок в Safari сначала дожидается фактического включения аудио браузером, после чего воспроизводит повторяющийся двухтональный сигнал попытки соединения до ответа или завершения вызова;
- добавлены регрессионные проверки регистрации, подсказок, присутствия, статусов сообщений, прочтения и гудков.

Не добавлялось в этот багфикс-релиз:

- группы, групповые звонки, отправка файлов и новая система приглашений. Эти функции оставлены за пределами релиза, пока исправляются известные ошибки основной переписки и звонков.

## Версия 0.6.2

Исправлено:

- голосовые сообщения, записанные на Android, теперь при наличии поддержки браузера записываются в MP4-контейнер вместо WebM, чтобы Safari на macOS не завершал такое голосовое сразу после запуска;
- изменение применяется только к Android: уже рабочее поведение записи на iPhone и Mac не меняется;
- если Android-браузер не умеет MediaRecorder в MP4, остаётся прежний fallback на WebM/Ogg;
- сервер голосовых сообщений теперь принимает `audio/mp4` и отдаёт его с исходным MIME-типом;
- добавлена регрессионная проверка серверной поддержки MP4 и порядка форматов Android.

Ограничение проверки:

- автоматические тесты не могут доказать реальное декодирование конкретной Android-записи Safari. Перед закрытием бага нужно живое испытание: записать новое голосовое на Android и полностью воспроизвести его на MacBook в Safari; отдельно убедиться, что новое голосовое с iPhone по-прежнему воспроизводится на обоих устройствах.

## Версия 0.6.1

Исправлено:

- после завершённого звонка голосовое сообщение больше не блокируется только из-за того, что на экране ещё показан итог звонка;
- итог звонка остаётся доступным для VoiceOver до следующего действия пользователя, а не исчезает сразу после завершения;
- для разговорных режимов звонка двухканальный захват повторно нормализуется в моно, если браузер фактически оставил два канала и из-за этого голос мог звучать только слева;
- при повторном применении моно сохраняются остальные настройки выбранного профиля микрофона;
- добавлена адаптация верхнего предела битрейта по фактическим WebRTC-статистикам исходящего потока: при тяжёлых потерях или большом RTT предел снижается быстро, при умеренных проблемах — после нескольких измерений, а повышается только после устойчиво хорошей сети;
- адаптация выполняется отдельно для каждого направления звонка, чтобы плохой канал одного участника не заставлял без причины ухудшать второй;
- добавлены регрессионные тесты завершённого звонка, каналов микрофона и адаптивного битрейта.

Ограничение проверки:

- автоматические тесты проверяют логику состояний и расчётов, но реальный двусторонний звук на Safari/macOS и iPhone всё равно нужно подтвердить живым звонком на двух устройствах, особенно при плохом интернете.
