# Bulbam protocol contracts

Этот файл фиксирует правила протокола до появления общего TypeScript-пакета.

## Идентичность

- `user_id` — стабильный серверный идентификатор аккаунта.
- `device_id` — стабильный идентификатор конкретной сессии/устройства.
- `username`, `display_name`, `phone` — изменяемые атрибуты и не могут быть внешними ключами истории сообщений.

## Сообщения

Каждая попытка отправки создаёт на клиенте `client_message_id` (UUID). При повторе после сетевого обрыва клиент обязан отправить тот же ID.

Сервер после сохранения возвращает собственный `message_id` и состояние `sent`.

Минимальные состояния:

- `pending` — существует только локально и ещё не подтверждено сервером;
- `sent` — сервер сохранил сообщение;
- `delivered` — хотя бы одно устройство получателя подтвердило получение;
- `read` — получатель открыл сообщение/диалог согласно будущим правилам read receipts;
- `failed` — действие не было принято сервером и требует решения клиента.

## События

WebSocket доставляет живые события, но не является единственным хранилищем. После переподключения клиент должен получать пропущенные изменения с сервера.

Каждое серверное событие в будущем должно иметь монотонный курсор/sequence для безопасной синхронизации.

## Медиа

Сообщение хранит метаданные медиа и ссылку/ключ объекта. Содержимое больших файлов не кодируется в base64 внутри событий чата.

## API envelope

Успех:

```json
{ "ok": true, "data": {} }
```

Ошибка:

```json
{ "ok": false, "error": { "code": "machine_readable_code", "message": "Human readable text" } }
```

`GET /api/health` является исключением первого bootstrap-этапа и пока возвращает компактный health payload.
