# Восстановление аудиозвонков Бульбама

## Устранённые ошибки

- Создание RTCPeerConnection single-flight: загрузка ICE и ответ собеседника не создают два конкурирующих соединения.
- WebSocket и HTTP poll обрабатывают сигналы последовательно; при временной ошибке SDP-сигнал не теряется.
- Offer, answer и ICE снабжаются идентификаторами согласования, чтобы устаревшие кандидаты не ломали новое соединение.
- Кандидаты ICE, пришедшие раньше нового offer, сохраняются в ограниченной очереди.
- Запрос восстановления, пришедший во время другого offer, выполняется после него.
- Safari autoplay: кнопка «Включить звук» вызывает audio.play() по нажатию без разрушения соединения.
- Если сеть отсутствует, восстановление продолжается после подключения. При STUN-only попытки разреживаются, чтобы не создавать бессмысленные запросы.

## Важное ограничение боевого окружения

На момент проверки GET /api/ready возвращает calls.ice=stun. В такой конфигурации WebRTC иногда не проходит через закрытый NAT или мобильную сеть. Нужен реальный TURN-relay с краткоживущими учётными данными.

Сервер поддерживает WEBRTC_TURN_URLS + WEBRTC_TURN_SECRET (HMAC credentials) или Cloudflare TURN key. Никогда не размещайте TURN shared secret или долговременный пароль в GitHub.

Wrangler OAuth на подключённом VPS пока не имеет разрешения workers:write. Следовательно, новый TURN secret нельзя безопасно передать в рабочий Worker с текущими полномочиями. Релеевую часть считать НЕ настроенной, пока calls.ice не станет turn+stun и не будут проверены звонки между настоящими устройствами.

## Проверка

npm test -- test/calls-client-recovery.test.js test/call-ice-generations.test.js

Тесты воспроизводят гонку загрузки ICE, фильтруют старые SDP/ICE и подтверждают, что восстановление autoplay не вызывает повторную WebRTC-неготиацию.
