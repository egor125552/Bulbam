# Собственный TURN для звонков Бульбама

Подготовленный сервер coturn находится на `169.58.224.216:3478` и принимает UDP/TCP. Пароль для выдачи временных реквизитов хранится только на сервере. Не добавлять его в файлы репозитория, результаты проверок или журнал Actions.

В `wrangler.jsonc` указаны адреса собственного сервера. Одного адреса недостаточно: Worker должен получить закрытый `WEBRTC_TURN_SECRET`.

## Подключение через GitHub Actions

В GitHub → Settings → Secrets and variables → Actions добавить три защищённых секрета:
- `BULBAM_TURN_SECRET`: значение, совпадающее с секретом coturn на сервере
- `CLOUDFLARE_ACCOUNT_ID`: ID аккаунта, которому принадлежит `bulbam-api`
- `CLOUDFLARE_API_TOKEN`: токен Cloudflare с минимальными правами редактировать секреты Workers для `bulbam-api`

Открыть Actions → Sync TURN secret to Cloudflare → Run workflow. Этот процесс отправляет значение в Cloudflare, но не записывает его в Git, не печатает в логах и не запускает отдельное развёртывание исходников. Существующая интеграция Cloudflare Workers Builds продолжает развёртывать само приложение.

## Проверка

После сборки и успешного Actions проверить `/api/ready`: `calls.ice` должен быть `turn+stun`. Затем провести настоящий звонок с двух разных сетей, открыть временную Диагностику звонка и убедиться, что при невозможности прямого соединения маршрут переключается на TURN. Само `turn+stun` означает только доступность резерва, а не то, что конкретный звонок уже прошёл через него.

При недоступном порте 3478 в некоторых сетях потребуется TURN over TLS на порту 443. Обновить конфигурацию сервера и адреса при наличии подходящего сертификата, а не объявлять такой вариант работающим без проверки.
