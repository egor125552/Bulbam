# Bulbam roadmap

## Phase 0 — bootstrap

- [x] Новый репозиторий без наследия Lenovo Messenger.
- [x] Один Cloudflare Worker `bulbam-api`.
- [x] Статический доступный веб-клиент.
- [x] `GET /api/health`.
- [x] Архитектурные правила и контракт сообщений.

## Phase 1 — accounts

Цель: стабильная идентичность пользователя, не зависящая от имени.

- приглашения для тестеров;
- регистрация одного аккаунта на приглашение;
- `user_id` и `device_id`;
- вход и безопасная серверная сессия;
- выход с отдельного устройства и со всех устройств;
- минимальный профиль пользователя;
- ограничения на массовую регистрацию и перебор приглашений.

Для этого этапа планируется подключить D1.

## Phase 2 — persistent direct messages

- создать/получить личный диалог;
- серверное хранение сообщений;
- `client_message_id` для идемпотентной отправки;
- состояния `pending`, `sent`, `delivered`, `read`, `failed`;
- загрузка истории после нового входа;
- офлайн-доставка;
- восстановление после обрыва без дублей и потерь;
- пагинация истории.

## Phase 3 — realtime sync

- WebSocket для живых событий;
- курсор событий и догрузка пропущенного после reconnect;
- несколько устройств одного аккаунта;
- presence/last seen;
- серверный heartbeat и очистка устаревших сессий.

## Phase 4 — media

- R2 для файлов;
- фотографии и документы;
- голосовые сообщения;
- безопасная загрузка и ограничения размеров;
- медиа остаются доступны после смены устройства;
- локальный кэш только как ускорение.

## Phase 5 — calls

Используем `MyMessenger` как лабораторию и переносим поведение, а не Swift-код.

- WebRTC signaling;
- ICE/STUN/TURN;
- Opus;
- адаптивный битрейт;
- обработка плохой сети;
- mute/output controls;
- состояния звонка и защита от stale signals;
- затем видео.

## Phase 6 — messenger features

- группы;
- каналы;
- блокировки;
- жалобы и антиспам;
- проверка подозрительных ссылок;
- редактирование/удаление сообщений;
- поиск;
- реакции и ответы.

## Phase 7 — Bulbam identity

Только после надёжного ядра:

- картофельные статусы;
- бульбы/подарки;
- выращивание картошки с друзьями;
- фирменные анимации блокировки;
- дополнительные premium-функции;
- эксперименты с заменой мата на «бульбу».

## Обязательные проверки каждого этапа

- Safari на iPhone;
- Safari на Mac;
- VoiceOver;
- клавиатурное управление;
- медленная/пропадающая сеть;
- перезагрузка страницы во время операции;
- повтор одной операции не создаёт дубликат;
- серверные данные переживают закрытие браузера.
