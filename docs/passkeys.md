# Ключи доступа Бульбама (WebAuthn / Passkeys)

Ключи доступа доступны всем пользователям Бульбама, а не только владельцу `egor125`. У каждого аккаунта собственный список ключей, который формирует системный менеджер паролей (например, iCloud Keychain) или аппаратный аутентификатор.

## Создание ключа
1. Войдите в Бульбам обычным способом.
2. Откройте **Настройки → Ключи доступа → Создать ключ доступа**.
3. Подтвердите действие через Face ID, Touch ID, пароль устройства или аппаратный ключ по запросу браузера.
4. Ключ сразу появится в списке. Удалить его можно там же. Настройка работает с VoiceOver: у каждой кнопки удаления есть название ключа.

## Вход
На экране входа есть кнопка **Войти с помощью ключа доступа**. Пароль и даже имя вводить не требуется, если на устройстве есть соответствующий ключ. Safari может также показать встроенную подсказку ключа в поле имени пользователя (`autocomplete="username webauthn"`). Если сеанс ещё действует, Бульбам сразу открывает чаты, без приглашения войти.

Если ключа доступа нет или системная проверка недоступна, остаётся старый вход по имени и паролю, а также восстановление по резервным кодам.

## Защита
- Приватный ключ никогда не отправляется в Worker и не хранится в D1. Сервер сохраняет только публичный ключ, счётчик использования и связанные с конкретным аккаунтом сведения.
- Для создания нового ключа требуется подтверждённая сессия. Каждый логин и выпуск ключа использует новый одноразовый challenge с 5-минутным сроком действия в D1. Атомарное списание защищает от повторного воспроизведения.
- Библиотека `@simplewebauthn/server` проверяет оригинал криптографической подписи, challenge, RP ID, origin и подтверждение пользователя (userVerification required). Подписанный ответ с постороннего домена или с другим ключом не даёт вход.
- RP ID закреплён за `bulbam-api.k69ysrndm7.workers.dev`, origin `https://bulbam-api.k69ysrndm7.workers.dev`. При будущем переезде на другой домен старые ключи на новый RP автоматически не переносятся, понадобится отдельная процедура.
- Сервер не выдаёт список пользователей или ключей анонимным клиентам. Список доступен только владельцу действующей сессии. Удаление чужого ключа запрещено.
- На публичное начало аутентификации действует ограничение количества challenge на Cloudflare IP. Для крупного сервиса в будущем следует включить более строгую защиту от бот-атак и журналирование.
- Вход через passkey создаёт обычную защищённую сессию, как парольный вход. После её истечения пользователь может снова воспользоваться сохранённым ключом.

## Важно
Само создание ключа требует подтверждения на пользовательском устройстве. Его нельзя выполнить за пользователя с VPS, GitHub или через API без системного диалога. Автоматизированные тесты проверяют API, отказ поддельным ответам и существующую регистрацию; для полного приёмочного тестирования требуются Face ID/Touch ID в Safari.
