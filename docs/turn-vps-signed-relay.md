# Бульбам: собственный TURN без нового секрета Cloudflare

Веб-клиент по-прежнему получает ICE-серверы с аутентифицированного /api/v1/calls/ice. Worker подписывает сервер-сервер запрос ключом VAPID, который уже существует только внутри Cloudflare для Web Push. Независимый сервис на VPS проверяет подпись открытым VAPID-ключом и создаёт временные учётные данные coturn на десять минут. Основной секрет coturn не покидает VPS, не попадает в GitHub Actions, Cloudflare или браузер.

Адрес сервиса: https://169-58-224-216.sslip.io/bulbam-relay-issuer/credentials. Caddy открывает только этот HTTPS-маршрут, сам Node-сервис слушает 127.0.0.1:18879. Вся логика выдачи находится отдельно в services/turn-issuer. Подписанные запросы привязаны к пользователю и времени, повторные запросы ограничены, подпись действительна в пределах 30 секунд. Участники не получают доступ к общему секрету.

Установка на VPS: скопировать services/turn-issuer/*.mjs в /opt/bulbam-relay-issuer, разместить открытый ключ из /api/relay/public-key в /etc/bulbam-relay-issuer/public-key, запустить systemd под пользователем turnserver с правом чтения /etc/turnserver.conf. В Caddy добавить handle_path /bulbam-relay-issuer/* с reverse_proxy на 127.0.0.1:18879. Важно: закрытый VAPID-ключ в файл не записывать, открытый не путать с закрытым.

Проверка: GET /api/health и /api/ready, публичный HTTPS health самого issuer, затем GET /api/v1/calls/ice с авторизованной учётной записью. Реальный звонок между разными сетями подтвердить через временный раздел диагностики в самом звонке. ICE turn+stun лишь означает, что резерв включён, но не подтверждает, что конкретный разговор использовал ретранслятор. Устройство при недоступном issuer продолжает пытаться создать прямое соединение через STUN.

При смене VAPID-ключей потребуется заново обновить публичный ключ на VPS. При смене секрета coturn достаточно перезапустить сервис выдачи временных реквизитов.
