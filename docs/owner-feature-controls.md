# Управление функциями и защитой переписок

## Настройки владельца

«Настройки» → «Управление функциями» доступно только аккаунту с ролью `owner`.
Первый переключатель: **«Защита переписки для всех аккаунтов»**.
Реализация расширяемая через таблицу `feature_flags`, но в этом выпуске поддерживается только `encryption`.

- При выключении глобальной настройки у всех пользователей скрываются кнопка «Защита» и подпись статуса защиты в шапке личного чата. Новые попытки активации защищённого режима запрещены сервером.
- При включении настройка возвращает раздел защиты. Новые сообщения в **уже защищённых чатах продолжают шифроваться**, даже если функция была временно скрыта: глобальное скрытие функции **не** превращает защищённую беседу в открытую. Это важно для сохранения конфиденциальности.
- Сервер сам проверяет роль владельца, принимать запрос только по наличию переключателя в интерфейсе нельзя. Обычный пользователь не может изменять глобальные настройки API.
- Клиенты обновляют состояние при входе, возвращении к приложению и в активной вкладке примерно раз в 30 секунд. Отдельные уведомления пользователям **не отправляются**.

## Настройка конкретного личного чата

В «Защита» доступны «Выключить защиту в этом чате» и «Включить защиту в этом чате». Это общее состояние диалога, видимое серверу и обоим участникам: не индивидуальная настройка пользователя.

После отключения **только новые** текстовые и голосовые сообщения идут открыто. Ранее зашифрованная история сохраняется без изменений, а локальные ключи остаются доступны для её расшифровки. Старые защищённые записи на устройстве, у которого нет прежнего ключа, могут остаться недоступны. При повторном включении нельзя подменять первоначальный ручной ключ автоматическим: Бульбам сохраняет `protection_origin` и возвращает тот же тип защиты. В автоматическом режиме клиент должен иметь исходный ключ устройства; в ручном режиме пользователь должен сохранить/импортировать исходный ключ.

Оба клиента узнают об обновлении состояния через `chat.updated` и актуальные данные чата, **без отдельных push, баннеров или сообщений об изменении настройки**.

## Ограничение автоматической активации

Автоматический ECDH пока не включён принудительно для каждого зарегистрированного аккаунта: в существующей реализации ключ привязан к **первому** устройству аккаунта, и безопасного подключения второго устройства ещё нет. Принудительная регистрация при каждом входе может навсегда заблокировать расшифровку истории на другом iPhone или Mac. Поэтому этот выпуск не выполняет потенциально разрушительную смену ключей. Автоматический обмен для аккаунтов, уже зарегистрировавших ECDH-ключ, продолжает работать. Для полной автоматизации нужны ключи устройств, доверенная привязка нового устройства и восстановление после потери первого.
