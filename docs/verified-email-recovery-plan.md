# Восстановление пароля по подтверждённой почте

## Сценарий
1. Пользователь открывает «Настройки» → «Безопасность аккаунта» и добавляет адрес электронной почты.
2. Бульбам отправляет ссылку подтверждения адреса. Адрес нельзя использовать для восстановления до успешного подтверждения.
3. На экране «Забыли пароль?» пользователь может запросить письмо на предварительно подтверждённый адрес.
4. Письмо содержит одноразовую ссылку на страницу Бульбама. Ссылка действует 15 минут. После перехода пользователь задаёт новый пароль, старые сеансы закрываются, а новый сеанс создаётся автоматически.
5. Резервные коды продолжают работать независимо от электронной почты.

## Безопасность
- Только пользователь, уже вошедший в аккаунт, может запросить подтверждение или замену адреса.
- Хранить в D1 только SHA-256 хеши криптографически случайных 256-битных токенов.
- Разделять токены подтверждения адреса и восстановления пароля.
- Сделать токены строго одноразовыми, с проверкой срока и атомарным списанием в транзакции.
- Не включать токены в серверные логи. В ссылках использовать URL-фрагменты, не отправляемые браузером серверу.
- На запросы восстановления возвращать одинаковый ответ независимо от того, существует ли адрес.
- Ограничивать частоту запросов для адреса и IP, а также число проверок токенов.
- Не изменять адрес электронной почты при вводе нового, пока он не будет подтверждён.
- Не принимать непроверенные адреса как доказательство владения аккаунтом.
- После сброса пароля отзывать прежние сеансы.
- Поддерживать отдельный доступный VoiceOver интерфейс для проверки почты и задания пароля.

## Альтернатива: полностью собственная отправка с VPS

Проверка существующего VPS (18 октября 2026): исходящий TCP 25 доступен, получен SMTP banner от Gmail, PTR адреса направлен на `vmi3528738.contaboserver.net`, проверка A записи через DNS Google совпала с IPv4 VPS. Docker установлен, на 25/587 сейчас нет активного SMTP-сервиса, свободно около 15 ГБ.

**Важно:** PTR от Contabo не является подконтрольным владельцу доменом отправки. Публиковать SPF/DKIM/DMARC для `contaboserver.net` нельзя. Одной PTR-записи недостаточно для доставки в Gmail.

Путь без покупки домена:
1. Получить бесплатный поддомен у <https://freedns.afraid.org/> (только если сервис допускает необходимые TXT-записи для конкретного выбранного shared-домена). FreeDNS поддерживает A, MX, TXT и ведёт публичные shared-домены. Для длительного применения выбрать домен владельца FreeDNS, а не произвольного пользователя, так как чужой общий домен может исчезнуть.
2. Установить минимальную исходящую почтовую очередь Postfix + DKIM-подпись (OpenDKIM). Полный IMAP/webmail комплекс Mailu не нужен, если задача лишь отправлять письма для подтверждения и сброса пароля.
3. Установить DNS: A для хоста отправки, SPF TXT отправляющего поддомена, DKIM TXT с публичным ключом и DMARC TXT. Уточнить правила FreeDNS для TXT внутри shared-домена. Проверить SPF/DKIM/DMARC, прямой и обратный DNS; желательно заменить PTR у Contabo на новый домен, но это требует доступа к их customer panel.
4. Не открывать публичный SMTP-relay! Postfix должен слушать только localhost, а входящие письма нам не нужны. Cloudflare Worker должен обращаться к защищённому HTTPS API на VPS с секретом и жёстким ограничением частоты; API ставит исходящие письма в локальную почтовую очередь.
5. Проверить реальную доставку на конкретный тестовый почтовый ящик до включения восстановления аккаунтов; отправка на порт 25 сама по себе не доказывает получение.
6. Оставить резервные коды для восстановления, если письмо не пришло. Shared бесплатный поддомен имеет больший риск блокировок и исчезновения, чем собственный домен.

## Работа без собственного домена: Brevo

Покупка домена не нужна для первого этапа восстановления почтой.

1. Зарегистрировать Brevo: https://app.brevo.com/
2. Добавить адрес отправителя в **Settings → Senders, Domains & Dedicated IPs → Senders** и подтвердить кодом, пришедшим на обычную почту (например, Gmail).
3. Учесть, что при неподтверждённом домене Brevo может подменять From на адрес под управлением Brevo, в частности `@t-sender-sib.com` для транзакционных писем. Это не означает взлом. Проверить реальную доставляемость и папку «Спам».
4. Создать API-ключ в **Settings → SMTP & API → API Keys**, но **не помещать** ключ в GitHub, исходный код, браузер или чат. Хранить только в Cloudflare Worker Secret `BREVO_API_KEY`.
5. Заполнить Worker переменные `BREVO_SENDER_EMAIL` (подтверждённый адрес отправителя) и `BREVO_SENDER_NAME=Бульбам`.
6. Worker отправляет сообщения напрямую запросом `POST https://api.brevo.com/v3/smtp/email` с заголовком `api-key` на стороне сервера. Пример JSON: `{ "sender": {"email": "...", "name": "Бульбам"}, "to": [{"email": "..."}], "subject": "...", "textContent": "..." }`.
7. Пока секреты и подтверждённый отправитель не настроены и отправка не проверена, функция «Восстановление по почте» должна быть **отключена**, а старые резервные коды доступны.
8. Использовать рабочий URL приложения `https://bulbam-api.k69ysrndm7.workers.dev/` в ссылках подтверждения/сброса. Собственный веб-домен не нужен.
9. В настройках пользователь сначала подтверждает личный адрес, затем он может применять письмо для сброса пароля.

## Альтернатива при появлении домена: Cloudflare Email Sending

Cloudflare Email Sending пока не подходит, потому что ему требуется подключённый в Cloudflare DNS собственный домен.

## Инфраструктура Cloudflare
При появлении домена Cloudflare Email Sending поддерживает Worker binding `EMAIL`, но требует настроенный и подтверждённый почтовый домен в Cloudflare DNS.
Пример `wrangler.jsonc` (добавлять **после** настройки отправителя):
```json
{
  "send_email": [{ "name": "EMAIL" }]
}
```
Почтовую отправку нельзя включать для пользователей без реальной рабочей доставки. При отсутствии binding интерфейс должен явно говорить «Восстановление по почте ещё не настроено», а резервные коды должны оставаться доступны.

Документация: https://developers.cloudflare.com/email-service/api/send-emails/workers-api/

## Статус
Технический план: для запуска без домена выбран Brevo. Отправитель, API-ключ и доставка ещё не настроены. Не считать восстановление по email действующим до успешных интеграционных тестов.
