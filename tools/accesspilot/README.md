# AccessPilot Engine

Универсальный движок проверки доступности веб-интерфейсов. Работает с DOM, HTML, JavaScript, React/Vue и приложениями WebAssembly, которые предоставляют HTML/ARIA-интерфейс.

**Никаких инструкций «кнопка A делает X, кнопка B открывает Y».** AccessPilot получает настоящий экран, сам обнаруживает кнопки, ссылки, поля, переключатели, слайдеры и доступные элементы в открытом Shadow DOM. Нажимает их, исследует новые состояния и проверяет доступность через собственные проверки + axe-core/WCAG.

## Использование в любом другом проекте

Достаточно Node.js 20+, установленного Chromium и двух пакетов `playwright` и `axe-core`. Модуль `tools/accesspilot` можно скопировать в другой репозиторий, запустить `npm install` внутри этой папки, затем `npx playwright install chromium`.

Создайте файл `accesspilot.project.json`:

```json
{
  "version": 1,
  "name": "Моё приложение",
  "url": "http://127.0.0.1:8080",
  "mode": "explore",
  "screens": [
    {"name": "Главная", "selector": "main"},
    {"name": "Параметры", "selector": "[role=dialog]"},
    {"name": "Переписка", "selector": "#messages"}
  ],
  "limits": {"maxActions": 250, "maxStates": 100, "maxDepth": 8}
}
```

Названия и селекторы экранов служат **только метками покрытия**, а не картой навигации. Если описаний нет, автоисследование всё равно работает. Действия при этом никак не прописываются.

Запуск:

```sh
node tools/accesspilot/cli.js --config accesspilot.project.json --output reports
```

Или один URL без файла, только безопасное чтение:

```sh
node tools/accesspilot/cli.js --url https://example.com --output reports
```

Для живых внешних сайтов **по умолчанию только аудит**: тестировщик не будет отправлять сообщения, менять настройки или удалять реальные данные. Режим исследования с нажатиями доступен для локальных приложений и явно изолированной тестовой среды.

## Экранный тестовый сервер и аккаунты

Если для теста нужны вход, сообщение, звонок или данные базы, используйте **provider**, который запускает временный тестовый сервер и обеспечивает готовность приложения. Это не список кнопок, а подготовка среды:

```json
{
  "version": 1,
  "name": "Мой сервис",
  "provider": "./test-provider.js",
  "mode": "explore",
  "scenarios": [
    {"name": "anonymous", "profile": "guest"},
    {"name": "authorized", "profile": "test-user"}
  ],
  "screens": [
    {"name": "Главная", "selector": "#app"},
    {"name": "Настройки", "selector": "#settings"}
  ]
}
```

Контракт provider:

```js
export async function createEnvironment(config) {
  // Запустить отдельное тестовое приложение и заполнить тестовую базу.
  return {
    url: "http://127.0.0.1:8080",
    isolated: true,
    async prepare({context,scenario}) {
      // Выставить тестовые cookie или localStorage.
    },
    async reset({page,context,scenario,url}) {
      await page.goto(url);
      // Дождаться готовности экрана и тестовых данных.
    },
    async close() {
      // Освободить временный сервер.
    }
  };
}
```

Ни `prepare`, ни `reset` **не говорят исследователю, что делает каждая кнопка**. Они лишь обеспечивают безопасную, воспроизводимую среду. Пример готового provider для Бульбама: `bulbam-provider.js`.

Можно использовать переменные окружения `ACCESSPILOT_SCENARIOS`, `ACCESSPILOT_MAX_ACTIONS`, `ACCESSPILOT_MAX_STATES` и `ACCESSPILOT_FAKE_MEDIA=1`. Для продолжения из контрольной точки предусмотрен `--resume`.

## Какие ошибки находятся

- Недоступные названия, неверные ARIA-роли, связи меток и полей, нарушения WCAG.
- Скрытые от скринридера интерактивные элементы, ошибки управления фокусом.
- Изменившиеся состояния кнопок, в том числе после нажатия и заполнения полей.
- Кнопки, которые удалось найти, но не удалось активировать или восстановить.
- Открытые компоненты Shadow DOM. Для слайдеров используется клавиатурное управление.
- Доступность холстов canvas: если нет даже альтернативного описания, это явно фиксируется.

Отчёт создаёт `accesspilot-report.json`, `accesspilot-report.txt`, отдельные отчёты сценариев и контрольные точки. Для описанных экранов видно, какие достигнуты, а какие нет. Число попыток и недостижимых действий не смешивается с количеством доказанных ошибок. Наличие «0 ошибок» не доказывает полный охват.

## Ограничения

Ни один универсальный инструмент не может **гарантированно** проверить все возможные состояния произвольной программы: потребовались бы все тестовые данные, системные разрешения, редкие ошибки сервера и внешние события. Исследование ограничено настройками глубины и количеством действий. Безопасность тестовой среды важнее принудительного выполнения опасных операций.

Если интерфейс WebAssembly рисуется **только на canvas/WebGL без HTML или accessibility API**, браузер не предоставляет отдельные кнопки для автоматического исследования. Нужен доступный DOM/ARIA-слой либо универсальный мост из движка приложения, экспортирующий роли, названия, состояния и действия. Вся модель приложения и её отдельные кнопки при этом в AccessPilot не описываются. Работа реального VoiceOver в Safari/iOS требует дополнительного теста на Apple-устройстве, Chromium не заменяет его.

## Запуск через GitHub Actions

В GitHub Actions достаточно установить Node.js, зависимости, Chromium, запустить ту же команду и загрузить папку `reports` как артефакт. Работающий образец: `.github/workflows/accesspilot.yml` в Бульбаме.
