# Правила разработки Bulbam

Bulbam — новый web-first мессенджер. Старые проекты Lenovo Messenger используются только как доноры идей и проверенной логики.

## Неподвижные правила

1. Не использовать отображаемое имя, username или телефон как внутреннюю идентичность аккаунта. У пользователя должен быть стабильный `user_id`.
2. Сервер — источник истины для аккаунтов, диалогов и сообщений. Клиентское хранилище — только кэш и очередь неподтверждённых действий.
3. Нельзя показывать сообщение как окончательно отправленное до подтверждения сервером.
4. Повторная отправка после обрыва сети не должна создавать дубликаты. Для клиентских операций нужен стабильный idempotency/client message id.
5. Доступность обязательна: семантический HTML, работа с клавиатуры, понятные названия элементов и проверка VoiceOver на Safari/iPhone и Mac.
6. Не добавлять визуальный UI ценой поломки screen reader UX.
7. Не копировать старый протокол Lenovo Messenger (`REGISTER:name:...`, общий пароль, глобальная комната) в новую архитектуру.
8. Большие медиа не передавать inline/base64 через WebSocket. Для них будет объектное хранилище.
9. WebSocket нужен для живых событий, но постоянные данные должны переживать отключение всех клиентов.
10. Звонки переносить только после устойчивой реализации аккаунтов и личных чатов.

## Порядок разработки

1. Web + Worker health/smoke.
2. Приглашения и аккаунты.
3. Сессии устройств.
4. Постоянные личные диалоги.
5. Отправлено / доставлено / прочитано и офлайн-доставка.
6. Медиа и голосовые.
7. Presence.
8. WebRTC/Opus звонки на основе опыта Lenovo Messenger.
9. Группы, каналы, безопасность и функции Bulbam.

При глубоких сетевых багах сначала установить точную причину логами или воспроизводимым тестом, затем исправлять и добавлять регрессионную проверку.
